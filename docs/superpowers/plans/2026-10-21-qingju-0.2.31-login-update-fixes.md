# 青橘 0.2.31 登录、签名与更新修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复青橘 Android 连续安装签名、登录品牌、GitHub OAuth 返回与 Release 更新检查，并发布可供朋友复测的 0.2.31。

**Architecture:** Android Release workflow 从 GitHub Actions Secret 恢复固定 debug keystore；登录页品牌从 `SiteIdentity.name` 生成；OAuth 在 GitHub 页面完成后通过青橘共享 WebView Cookie 与 `/session/current.json` 只读核验会话；更新器用纯 Dart parser 处理 `qingju-v` 标签和版本化 ARM64 APK 名称。

**Tech Stack:** Flutter/Dart、slang 4.14.0、Android Gradle Kotlin DSL、GitHub Actions、JDK 17 / `keytool` / `apksigner`。

## Global Constraints

- 固定签名只用于 Android debug 测试 APK；不提交 keystore、密码或 Secret 值。
- Actions Secret 名称为 `QINGJU_DEBUG_KEYSTORE_BASE64`；密钥别名 `androiddebugkey`，JKS store/key password 均为 `android`。
- 版本号更新为 `0.2.31+2026102102`，发布 tag 为 `qingju-v0.2.31`。
- `qingju-<version>-android-arm64-debug.apk` 等发布文件名必须保留版本号。
- 修改本地化源 ARB 后只用 `dart tool/gen_l10n.dart` 生成；不手改生成文件。
- 保留既有 `.workflow/` 与 `deliverables/private/` 内容，不添加到提交。
- 旧 0.2.29/0.2.30 APK 使用的私钥不可恢复；安装固定密钥签名包前需一次卸载旧包。

- [x] **Step 3: 实现 helper 和 WebView session recovery**

在 OAuth flow active 且当前顶层 URL 为 GitHub 时：
1. 用 `BoundarySyncService.instance.syncFromWebView(currentUrl: AppConstants.baseUrl, controller: controller, cookieNames: CookieJarService.authCookieNames, allowLowConfidenceSessionCookies: true, requestGeneration: _flowGeneration)` 回灌站点认证 Cookie。
2. 用 `_service.dio.get('/session/current.json', options: Options(extra: const {'skipAuthCheck': true, 'skipCsrf': true}))` 查询会话。
3. 响应含非空用户名时清除 OAuth 状态并加载 `AppConstants.baseUrl`，让原有 `_checkLoginStatus` 完成 cookie/token 收口。
4. 用 in-flight 标志防并发；请求错误或 guest 不导航、不登出、不记录 cookie/token。

在 `onLoadStart` 识别 `/auth/github` 开始 OAuth 流程；在 `onLoadStop` 与 `onUpdateVisitedHistory` 的 GitHub 页面分支触发恢复；离开 OAuth 回到普通青橘登录页时清理状态。
