# 青橘客户端实现与验收计划

**目标：** 执行已批准的青橘专用客户端目标契约；不新增审批、不发布正式版本。

**架构：** 保留 Flutter、Discourse 服务、Cookie 边界同步和现有布局。青橘配置独立于 Linux.do 插件；认证走现有完整站点 WebView，避免复用原站硬编码验证码。原生应用标识、深链与存储命名一起隔离。CI 仅上传验收 artifacts，不发 Release。

## 检查点
- [ ] 记录基线提交、初始化子模块，创建并核实 GitHub fork 与本地适配分支。
- [ ] 为 `lib/constants.dart`、青橘配置和登录路由补充站点隔离测试；把基础地址、内部链接策略、登录入口和专属功能按青橘适配。
- [ ] 在 Android、Apple、Windows、Linux 平台配置及原生通道中统一独立标识 `me.qingju.client`，显示名「青橘」，替换品牌图标；保留内部 package 名以避免无关重构。
- [ ] 新建独立的五平台非发布工作流，先生成 l10n/证书与 Rust 原生产物，再实际构建、打包和上传 artifacts；保留原有静态检查和测试。
- [ ] 用同一 Flutter 版本执行基线及适配后的 analyze/test，保存差异和日志；修复新增问题，不掩盖基线失败。
- [ ] 推送青橘分支并运行五平台 CI；下载 artifacts，记录提交 SHA 与 SHA-256。
- [ ] Windows 本机启动验收真实读取功能，等待用户完成登录并指定测试区域后验证写操作；无法取得配合时明确标记阻塞。
- [ ] 更新中文构建说明、术语表与逐项验收矩阵；只上传去隐私的项目文件。
