# 青橘 0.2.32 登录、签名与更新修复设计

## 背景与已确认根因

本次收到朋友对 `qingju-v0.2.30` 的四项反馈：Android 包不能覆盖安装；登录页工具栏仍显示 LINUX.DO；GitHub OAuth 成功后停在 GitHub；手动检查更新报 `FormatException`。

1. Android Release workflow 在 GitHub 临时 runner 上执行 `build apk --debug`。`android/key.properties` 不存在，Gradle 选择默认 debug signing；runner 每次密钥不同：本机 `apksigner` 测得 0.2.29/0.2.30 signer SHA-256 分别为 `8a6b4e18e62075e0707e0d82187974538dd4dc17fe68d7deccb4ba181cddc7f6` / `472300a07cf87f24a0a75040ed753a727d07692c1a9f3244fbbf4d507cea50dd`。0.2.31 CI 的 Secret 解码成功，但 `Prepare` 仍输出 `Android local signing: incomplete config`，证实仅恢复 `~/.android/debug.keystore` 不足；Gradle 要求完整 `android/key.properties` 才将固定 keystore 配置用于 debug。
2. `WebViewLoginPage` 工具栏读取 `webviewLogin_title`；四种 ARB 本地化都把站点名写死为 `LINUX.DO`，而站点规范名已在 `SiteIdentity.name` 定义为“青橘”。
3. 青橘 `/auth/github` 的 OAuth 首跳指向 `github.com/login/oauth/authorize`，回调是 `https://qingju.me/auth/github/callback`。应用只从当前 WebView DOM 读取论坛用户名；WebView 留在 GitHub 域时没有查询青橘会话并恢复到论坛首页的路径。第二次点击直达论坛与第一次 OAuth 已建立论坛会话、但应用没有收口相符。
4. 更新器将 Release tag 用 `replaceAll('v', '')` 处理；`qingju-v0.2.30` 因而成为 `qingju-0.2.30`，随后按点拆分并 `int.parse`，触发截图中的 `qingju-0` 解析错误。修复 tag 后还需识别发布包名 `qingju-0.2.32-android-arm64-debug.apk`；现有架构过滤只识别 `arm64-v8a`。

## 目标与验收标准

- 后续 GitHub Actions Android 测试包统一使用仓库 Actions Secret 中的固定 debug keystore；secret 缺失或无法验证时构建失败，不回退生成新证书。
- 登录工具栏从 `SiteIdentity.name` 获取站点名，简体、繁体及英文均不再硬编码 Linux.do。
- GitHub OAuth 流程留在 GitHub 页面时，应用从共享 WebView Cookie 同步青橘认证 Cookie，并以 `/session/current.json` 为成功判据；确认已登录后回到 `AppConstants.baseUrl`，沿用现有登录收尾和会话广播。未认证时保持当前 OAuth 页面，不中断流程。
- 更新检查正确解析 `qingju-v0.2.32` 及传统 `v0.2.32` tag，并把版本化 Android ARM64 debug APK 识别为 `arm64-v8a`。
- 发布 `0.2.32+2026102103`，APK 文件名保持带版本号；不改写已发布的 `qingju-v0.2.31` tag。
- 不把 keystore、Secret、个人截图或 `.workflow/` 纳入 Git；不改站点服务器配置、非登录页面的 Linux.do 业务集成、原生 splash 或桌面图标。

## 设计

### Android 测试签名

生成一次 JKS debug keystore（alias `androiddebugkey`、store/key password `android`），只通过 `QINGJU_DEBUG_KEYSTORE_BASE64` GitHub Actions Secret 保存。Android job 在构建前解码到 `$HOME/.android/debug.keystore`，限制文件权限并用 `keytool -list` 验证；随后在 runner 写入被 `.gitignore` 忽略的 `android/key.properties`，四项分别为该 keystore 绝对路径、alias 和两项密码。`build.gradle.kts` 由此令 `hasReleaseSigning=true`，让 debug 变体明确使用该 release signing config；`Build Android ARM64 debug signed` 日志应显示 `Android local signing: using .../debug.keystore for debug/profile/release`。

旧 0.2.29/0.2.30 私钥不能从 APK 证书恢复；0.2.31 虽恢复 keystore 文件，但 Gradle 实际仍用临时默认 signer。0.2.32 固定配置后，已安装的 0.2.30/0.2.31 包必须一次卸载重装；后续同证书 CI 包可以覆盖更新。

### 登录品牌

将 `webviewLogin_title` 改为带 `siteName` placeholder 的翻译模板，`WebViewLoginPage` 传入 `SiteIdentity.name`。由 `dart tool/gen_l10n.dart` 生成代码，不直接手改生成文件。

### GitHub OAuth 回归

给登录页增加受限 OAuth 状态：仅在青橘 `/auth/github` 流程启动后监测 `github.com` 顶层页面。每次 GitHub 页面完成加载时，先通过 `BoundarySyncService.syncFromWebView(currentUrl: AppConstants.baseUrl, ...)` 同步青橘会话 Cookie，再向 `/session/current.json` 发起只读 session probe。只有响应存在非空 `current_user.username` 时，才清除 OAuth 状态并导航到青橘首页；Guest/错误响应不改 URL，不登出、不记录 Cookie 值。页面回到青橘域后继续使用既有 `_checkLoginStatus` / `_finalizeLoginBeforeExit` 流程。

把 GitHub URL 判定和 current_user 响应解析放入可单测的小型 helper，避免 widget 测试必须启动原生 WebView。

### 更新器

在 `UpdateService` 使用纯 Dart 的 release metadata parser：按精确前缀移除 `qingju-v`、`v` 或 `qingju-`，并校验剩余值为三段或四段数字版本（与 Release workflow 的版本格式一致）；版本比较逐段比较。APK 架构解析保留现有 `arm64-v8a`、`armeabi-v7a`、`x86_64` 支持，新增把 `android-arm64-debug` 映射到 `arm64-v8a`。

## 验证

- 单测覆盖带/不带前缀的三段与四段版本 tag、版本比较、`qingju-0.2.32-android-arm64-debug.apk` 架构映射，以及 GitHub host / Guest / authenticated `current_user` 解析。
- 运行 `dart tool/gen_l10n.dart --check`、相关 `flutter test --no-pub`、定点 `dart analyze`、`dart format --output=none --set-exit-if-changed` 和 `git diff --check`。
- 五平台 Release CI run `39536579869` 全部成功，Android 构建日志明确显示 Gradle 使用固定 keystore；下载 Android APK、`BUILD-android.txt`、`SHA256SUMS-android.txt` 后，APK 哈希、tag commit 和 signer 证书指纹逐项匹配。
- 朋友真机上的 GitHub OAuth 交互仍需登录账号实测；CI 不执行真实账号登录。
